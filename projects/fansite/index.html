Why I built it

I wanted a fansite that felt like part of 86 Eighty-Six rather than another wiki.

Fan wikis cover the facts but none of the mood. I wanted something that felt like sitting at a Handler's console: plot breakdowns, processor dossiers, mech specs and faction profiles, all presented as classified HQ records.

How it works

You log in as a Handler, so every page is built as a screen on HQ's terminal.

A Vite and React app with six routes for home, intel, characters, arsenal, factions and missions. Tailwind v4 holds the design tokens, tsparticles draws the ember particles, and a boot sequence plays the first time you open the site in a session. It's deployed as static files on GitHub Pages.

Technical decisions

404.html redirect for deep links

GitHub Pages only serves files, so refreshing /characters would 404. The 404 page redirects to the app with the path in a query parameter, and the app restores it before rendering.

Tailwind v4 with @theme tokens

The terminal colours and fonts live in one @theme block through the Vite plugin, with no separate config file.

CRT scanlines in pure CSS

The scanlines are a repeating gradient of 2px dark lines every 4px, written as a Tailwind arbitrary value, with vignette layers on top.

Boot sequence once per session

A sessionStorage flag is read when the component first sets its state, so the intro doesn't flash and replay when you come back to the home page.

Challenges & reflections

  • The boot sequence prints each line after a random 500-900ms delay. Leaving the page mid-boot clears every pending timeout, so nothing fires after you've gone.
  • On phones, picking a processor scrolls back to the top so their dossier is in view.
