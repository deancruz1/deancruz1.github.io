Frontend

Urara

A fan guide to Umamusume Pretty Derby with character profiles, music previews, news and birthdays.

Live siteCode
ReactTypeScriptTanStack QueryTailwindFramer Motion

Why I built it

Existing Umamusume resources are scattered across wikis, YouTube playlists, and social media. Fans have no single destination to browse profiles, preview music, and catch up on news. I wanted to build that unified experience.

How it works

Built a single-page React app with four main sections: character browser, music catalog, news feed, and birthday calendar. All data comes from the Umapyoi API via TanStack Query for caching and state management. The MyMemory API handles translations without any API key. Tailwind CSS and Framer Motion handle the responsive layout and animations.

What it does

Character profiles

Bios, stats, fun facts, voice samples and an image gallery with a lightbox.

Translation

Japanese profile text translates to English on demand through the MyMemory API, with a toggle back to the original.

Music browser

Filter tracks by character and play previews.

News feed

Keyword search, pagination and full articles in a modal.

Birthday calendar

Today's and this month's upcoming character birthdays.

Accent colours

Each character's primary colour drives the buttons, borders and highlights on their page.

Decisions

TanStack Query

Handles caching, background refetching, and loading states out of the box - cleaner than managing useEffect chains for every API call.

Umapyoi API

Free, no authentication required, and provides all the character, music, and news data needed. The community maintains it actively.

GitHub Pages

The app is fully static with no server-side logic. All API calls happen client-side, so free static hosting was the obvious choice.

MyMemory API for translation

Machine translation of Japanese text to English without any API key setup or rate limit concerns for a fan project of this scale.

Challenges

  • The Umapyoi API returns raw HTML in news content, so the news detail modal had to safely render HTML strings while avoiding XSS vulnerabilities
  • Designing a responsive character filter that works as a vertical sidebar on desktop but a horizontal scroll row on mobile required two distinct layout strategies

What I'd do differently

  • Implement static site generation (SSG) for character and music pages so search engines can index API-driven content
  • Add user accounts with Supabase to enable favouriting characters and saving music playlists
  • Add music search filters by album, artist, and song type beyond just character filtering
