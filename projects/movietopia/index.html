Movietopia · the reviews page, logged inCode ↗

Why I built it

A graded assignment for my server-side programming module.

The module asked for a working CRUD web app. I used it to understand how sessions, relational tables and create, read, update and delete operations fit together end to end.

How it works

Procedural PHP with mysqli and PHP sessions, running locally on XAMPP.

Three MySQL tables (users, movies and reviews) behind server-rendered PHP pages. You can register, log in, search and sort movies, and write, edit and delete your own star-rated reviews.

Technical decisions

Foreign keys with cascades

Reviews depend on both a movie and a user, so the schema enforces that and cleans up a user's reviews when the account goes.

Session flags for the navbar

One logged-in check in each template switches between the guest and member navigation.

Remember me with a cookie

Ticking it stores your username in a long-lived cookie, and the login form fills it in.

Challenges & reflections

  • Every Edit and Delete button is named after its review ID, so the handler loops through the possible IDs to work out which row was clicked.
  • Add Review can be opened from a movie's page or from the header, so the form has to handle arriving with or without a movie already chosen.
  • Next: Move every query to prepared statements. They're built by joining strings at the moment.
  • Next: Hash passwords with password_hash instead of storing them as plain text.
  • Next: Check on the server that a review belongs to you before editing or deleting it, and escape user text with htmlspecialchars.
